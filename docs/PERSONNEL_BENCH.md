# Personnel telemetry bench setup

Use a fictional workspace and above-ground ESP32 development hardware. The endpoint is a software bench interface. Underground suitability, signal coverage, battery life, and SOS delivery under degraded conditions require separate validation.

## Local setup

1. Build with `npm run build`. Launch `npm run preview` on the local server with SQLite persisted to disk and `MESSAGING_MODE=dry-run`. Start the existing local Python simulator when running escape scenarios. See the README for the local preview commands and prerequisites.
2. Open the workspace on the trusted LAN and copy its ID from `GET /api/workspace/state` in the signed-in browser. Keep the same session/database for the bench run. The preview's anonymous workspaces are for isolated demonstrations. Use HTTPS when accessing browser features that require a secure context from another device.
3. Set `FORESIGHT_PERSONNEL_MINE_ID` to that workspace ID. Generate an independent random gateway secret with `openssl rand -hex 32` and set `FORESIGHT_PERSONNEL_GATEWAY_TOKEN` on the server and gateway. Restart the server after setting both. The endpoint is disabled otherwise. Use an isolated LAN or TLS and keep the token off wearables and out of browser code.
4. Under **Underground now → Personnel observations → Sensor network**, register a physical receiver in an existing zone and assign a physical wearable to a person. Use **Manual check-in** to put the person on the declared roll. Sensor events do not create or close check-ins.

## Gateway contract

POST to `/api/telemetry/personnel` with `Authorization: Bearer <gateway-secret>` and JSON. Example payload, with provisioned IDs and a current timestamp:

```json
{
  "mineId": "<workspace UUID>",
  "eventId": "<stable ID generated by the wearable or gateway>",
  "deviceId": "<wearable code>",
  "receiverId": "<receiver code>",
  "type": "observation",
  "observedAt": "<ISO 8601 observation time with offset>",
  "sequence": 1,
  "rssi": -65,
  "batteryPercent": 84
}
```

The gateway submits `heartbeat` without a wearable ID, `observation` for a periodic detection, and `sos` for a button press. RSSI and battery are optional. The server adds receipt time. Reuse the exact packet on HTTP timeout or server errors. Multiple receivers forwarding the same SOS should use the same wearable event ID. Delayed packets preserve the last-known state and late SOS remains an auditable alert. Acknowledge in the UI, then use the existing emergency and muster controls for human reconciliation.

For the first bench test, forward observations at a low rate. Timestamp them at the receiver or gateway and synchronize clocks. Persist queued packets on the gateway before sending, retain them through disconnects, and retry unchanged after reconnect. This milestone supplies the HTTP endpoint. A gateway spool implementation and device firmware are outstanding. The server currently projects the latest receiver's zone. RSSI filtering, multi-receiver hysteresis, credential rotation per receiver, and RF calibration are outstanding. Test stale state by stopping packets for at least 90 seconds and refreshing the workspace.

Set `FORESIGHT_PERSONNEL_DEMO=1` on an isolated fictional workspace to use the **Demo** source and trigger an observation or SOS. Demo registrations and alerts are separate from the physical projection and are excluded from observed data captured by escape runs. The escape engine still uses the declared or supervisor-selected starting assumptions. The saved run preserves physical last-known context alongside them.

RFID registration stations, motion/fall classification, and on-device SOS delivery guarantees need separate bench work. No exercise should depend on automatic checkout or injury inference from signal loss.
